## What to build

Provide reproducible evidence that the connected account journeys and protected workspaces work together in a real localhost browser, with technical completion clearly distinguished from real-user activation. Each preceding ticket owns its own tests; this ticket validates the joined journey and records remaining blockers.

Source: [S01 specification](https://github.com/AxIon-200/aventix-development/issues/107#approved-s01-specification). Use the approved existing public application HTTP boundary: injected fetch for frontend contract cases, the backend application factory with real Better Auth/Prisma on the guarded dedicated PostgreSQL test database, and actual browser checks. The user approved this test seam with the breakdown on 2026-10-21.

## Acceptance criteria

- [ ] Run updated frontend authentication/public tests, frontend typechecking and production build, backend authentication lifecycle suites on the dedicated test database, and appropriate backend static checks for changed code. Preserve all test/development database identity/separation guards; missing infrastructure is a recorded blocker, never a passing check.
- [ ] Walk registration/current terms through new mail verification and separate login; delivery-failed account creation/resend; duplicate registration; legacy consent; legacy mandatory reset; recovery/reset; password reuse; verification with the new password; and retained disabled/unverified restrictions. Use controlled fixtures/mail without claiming real activation.
- [ ] Exercise new and existing verification/reset links, immediate fragment stripping, explicit bridge Continue, reload/reopen instructions, wrong-password verification retry, invalid/expired/used links, and signed-in completion including reset of another account's browser cookie.
- [ ] Verify actual browser-to-proxy-to-API credentials, cookie persistence after reload/browser reopening within original expiry, mutation Origin, meaningful IP throttling and spoofing resistance. Document intentional local IP aggregation; localhost results do not establish production proxy trust.
- [ ] Exercise safe and rejected returns throughout original-browser flows, fresh email tabs/devices, account choices when already signed in, navigation/focus/cross-tab refresh and late-response races, confirmed logout, lost-logout reconciliation, and uncertainty when reconciliation also fails.
- [ ] Verify direct and client-navigated nested protected pages for guests and every role pairing, plus stale/revoked/disabled sessions, service outages, no protected-content leakage, no role switches, and unavailable unfinished workspaces with real identity and no personal sample records.
- [ ] Check lost mutation responses without automatic retries and privacy-preserving resend/recovery cooldowns plus Retry-After. Preserve existing backend rollback, replay, concurrency and native-route-denial coverage rather than replacing lifecycle tests with mocked internals.
- [ ] Record commands/results and browser observations without passwords, tokens, mail bodies, or provider payloads. Repair integration defects found by this walkthrough, within S01 scope, and record blockers honestly.
- [ ] Record activation separately: genuine reviewed terms/document/version, configured real sending and smoke evidence, restricted owner-mailbox versus arbitrary-recipient delivery, actual-account inventory and working recovery before legacy activation, and separately approved production HTTPS/cookie/proxy verification. Do not author terms, configure real credentials, send provider mail, operate on live accounts, or deploy under this ticket.

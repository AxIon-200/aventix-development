## What to build

Let a prospective attendee read current terms and register a valid account, receive a verification email, and recover from initial delivery failure without duplicate registration.

This ticket implements only its slice of parent #33's approved specification. Use HTTP integration tests with real Better Auth/Prisma, the verified isolated test database, and controlled email delivery. Include the relevant persistence, safe response/error contracts, policy enforcement on native routes, and focused tests; no frontend work is required. Retain the school-project scope. Publishing or labeling this ticket does not authorize implementation: ticket 1's prerequisites and explicit separate implementation approval remain mandatory.

## Acceptance criteria

- [ ] Provide public current-terms version/document URL retrieval; require true acceptance of the current version and record its server-generated timestamp.
- [ ] Successful registration returns 201, creates only an ACTIVE ATTENDEE with unverified email, and issues no session; role/status/verification/consent metadata remain server controlled.
- [ ] Normalize emails by surrounding trim and lowercase while preserving dots/plus suffixes. Reject duplicates, including unverified accounts, with a conflict and no existing-account mutation.
- [ ] Validate names at 1–100 Unicode code points after surrounding trim, derive the authentication name, and validate exact untrimmed passwords at 15–128 code points with spaces/Unicode allowed.
- [ ] Accept optional Philippine mobile numbers only as 09 plus nine ASCII digits or +639 plus nine ASCII digits; normalize to +639 form, without carrier-prefix/ownership checks.
- [ ] Attempt real verification email delivery through the approved provider, using captured delivery in tests. Initial eligible attempt starts a 60-second verification cooldown even when delivery fails.
- [ ] On email failure retain the account and consent, issue no session, and return 503 ACCOUNT_CREATED_EMAIL_FAILED explaining resend availability. Apply agreed JSON errors, IP limits, origin/CSRF protections as applicable, and native-route bypass prevention.
- [ ] Verify the full HTTP registration path with real Better Auth/Prisma and the isolated test database, covering validation, duplicates, consent, protected inputs, absence of session, and delivery failure.

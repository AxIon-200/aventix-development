## What to build

Let eligible users log in, read their own permitted account profile, retain fixed-life sessions across browser closure, and end the current session reliably.

This ticket implements only its slice of parent #33's approved specification. Use HTTP integration tests with real Better Auth/Prisma, the verified isolated test database, and controlled email delivery. Include the relevant persistence, safe response/error contracts, policy enforcement on native routes, and focused tests; no frontend work is required. Retain the school-project scope. Publishing or labeling this ticket does not authorize implementation: ticket 1's prerequisites and explicit separate implementation approval remain mandatory.

## Acceptance criteria

- [ ] Unknown emails and incorrect passwords return the same invalid-credentials response. Reveal disabled/unverified/missing-consent access gates only after correct credentials; disabled takes precedence over unverified.
- [ ] Require ACTIVE status, verified email, and genuine recorded consent before login and protected account access. Existing sessions cannot bypass access gates.
- [ ] Successful login returns 200 with permitted account information and session credentials in cookies, never JSON bodies. Preserve the approved public-field allowlist.
- [ ] GET /api/v1/me returns only the authenticated account's permitted profile; unauthenticated requests fail safely and there is no arbitrary-user lookup.
- [ ] Sessions last exactly seven days from issuance for every role; activity does not renew them. Cookies persist across closure no later than original expiry, with no Remember Me variation. Concurrent device sessions are independent.
- [ ] Logout invalidates only the requesting session, clears its cookie, and returns 200 even for missing, expired, or invalidated sessions.
- [ ] Apply verified production cookie flags, explicit credentialed CORS/trusted origins, CSRF protections, IP limits, current server-side status checks, safe responses, and policy enforcement on direct Better Auth routes.
- [ ] Demonstrate cookie/session behavior, expiry, concurrent devices, gated profile retrieval, invalidation, repeated logout, origin/CSRF rejection, and direct-route bypass prevention through real HTTP integration tests.

## What to build

Let unverified email owners complete verification with a link and their current password, or request another email without leaking account state.

This ticket implements only its slice of parent #33's approved specification. Use HTTP integration tests with real Better Auth/Prisma, the verified isolated test database, and controlled email delivery. Include the relevant persistence, safe response/error contracts, policy enforcement on native routes, and focused tests; no frontend work is required. Retain the school-project scope. Publishing or labeling this ticket does not authorize implementation: ticket 1's prerequisites and explicit separate implementation approval remain mandatory.

## Acceptance criteria

- [ ] Verification requires an account/purpose-bound link valid for 24 hours and the account's current password. Success returns 200 without issuing a session; a separate login is required.
- [ ] Wrong passwords do not consume otherwise-valid links. Invalid, expired, consumed, and wrong-purpose links fail safely without account details, using the approved link error contract.
- [ ] Resending preserves earlier links until their own expiry or successful verification. Successful verification invalidates all outstanding verification links, including during concurrent submissions.
- [ ] For validly formatted addresses, resend returns HTTP 200 and the approved generic message across missing, verified, eligible, cooldown-suppressed, and delivery-failure cases.
- [ ] Enforce the independent 60-second verification cooldown from eligible attempt initiation, including failed delivery. Suppressed requests send nothing and do not extend it.
- [ ] Disabled accounts may verify with link/password but remain disabled and receive no session. Login never implicitly resends verification mail.
- [ ] Use approved destinations and secret-safe failure logging; apply agreed IP limits, public-route enforcement, safe errors, and HTTP tests for success, expiry, replay, races, password gating, and privacy.

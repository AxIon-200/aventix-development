## What to build

Let account owners recover through their inbox, including unverified and disabled owners, while removing prior session access and preserving all access gates.

This ticket implements only its slice of parent #33's approved specification. Use HTTP integration tests with real Better Auth/Prisma, the verified isolated test database, and controlled email delivery. Include the relevant persistence, safe response/error contracts, policy enforcement on native routes, and focused tests; no frontend work is required. Retain the school-project scope. Publishing or labeling this ticket does not authorize implementation: ticket 1's prerequisites and explicit separate implementation approval remain mandatory.

## Acceptance criteria

- [ ] Recovery request returns HTTP 200 and the approved generic message for valid addresses across unknown, active, disabled, unverified, cooldown-suppressed, and delivery-failure outcomes.
- [ ] Use an independent 60-second per-normalized-address reset-email cooldown starting at eligible attempt initiation even on failure; suppressed requests send nothing and do not extend it. Apply documented IP limits.
- [ ] Reset links are account/purpose bound, valid for 30 minutes, and prior links survive new requests until expiry or successful reset.
- [ ] Reset requires a valid new password under the approved exact Unicode policy and rejects the current password. Successful reset consumes all outstanding reset links, invalidates every session, returns 200, and issues no replacement session.
- [ ] Reset neither verifies email nor changes DISABLED status. Existing verification links retain their original validity but verification requires the new current password.
- [ ] Prevent replay, purpose substitution, and concurrent-use violations. Validate destinations, keep tokens/passwords out of logs, and persist successful-reset audits.
- [ ] Verify real HTTP flows using captured mail and multiple sessions, including expiry, privacy, failed delivery, cooldown, disabled/unverified fixtures, concurrent submissions, unchanged access gates, and direct-route enforcement.
